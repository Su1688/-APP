## 功能

- **点菜**：22 道家常菜，7 个分类，支持按菜名 / 描述 / 标签搜索，本店招牌会根据历史点单自动出现
- **购物车**：底部悬浮栏 + 半屏面板，可加减份数、写备注、选「什么时候想吃」
- **订单**：「待接单 / 制作中 / 已完成」三段状态流转，带进度时间轴，可催单、可取消、可「照这个再来一单」
- **收藏**：菜品详情页点爱心收藏，收藏页可一键加进菜单
- **菜单管理**：加新菜、改菜名/图/分类/标签/食材/做法、标记「今日售罄」、下架、一键恢复默认菜单
- **菜品照片**：加菜 / 改菜时可以拍一张自己做的，她看到的就是实物；没拍照的菜回落到 emoji
- **我的**：头像昵称、点菜统计（点过多少单、吃掉多少份、最常点的是谁）、辣度与忌口偏好
- **大厨模式**：在我的页切换身份，订单里就会出现「接单开做 / 做好啦」按钮
- **双人同步**：用 6 位邀请码把两台手机配成一个「小家」，菜单、订单、口味偏好自动同步

## 菜单是怎么存的

`data/dishes.js` 里的 22 道菜是**只读的默认菜单**，你在小程序里做的改动都叠在它上面，
分三份存在本地 Storage：

- `dc_menu_custom`：你自己新增的菜
- `dc_menu_overrides`：对默认菜的修改（改名、换图、售罄等）
- `dc_menu_deleted`：被你删掉的默认菜

所以「恢复默认菜单」只要清空这三份数据就能一键还原，不会破坏源码。
读取菜单统一走 `utils/menu.js` 的 `getAll()` / `getDish(id)`，
页面里不要再直接 `require("../data/dishes.js")`。

售罄的菜会**置灰留在菜单里**（她能看到「今日售罄」），但加不进购物车；
改菜单时如果某道菜正在购物车或收藏里，会被自动清理，不会留下无效条目。

## 菜品照片存在哪

菜品有一个 `image` 字段，留空时回落到 `emoji`。

| 菜品来源 | `image` 存什么 | 她看得到吗 |
| --- | --- | --- |
| 打包进包的默认菜 | `/assets/dishes/xxx.jpg` | 看得到，图跟着小程序包走 |
| 你自己加的菜（已配云开发） | 云存储的 `cloud://` fileID | 看得到，跟着菜单同步过去 |
| 你自己加的菜（没配云开发） | 本机用户目录 `wxfile://usr/` | 看不到，编辑页会提示 |

`wx.chooseMedia` 返回的是**临时路径**，重启小程序就失效，不能直接存进菜品数据 ——
落地这一步统一在 `utils/image.js` 里处理（云可用就传云存储，否则 `saveFile` 到本机）。
删菜或换图时会顺手删掉旧图；打包在包里的默认图不动。

它是一个**独立的静态页面**（单文件、零依赖、离线可用），把小程序里的交互在浏览器里复刻了一遍：

能做的事：切分类、搜菜、加减菜、开购物车面板、改期望时间、写备注、下单、

它**不在小程序包里**（`project.config.json` 的 `packOptions.ignore` 已忽略 `preview`），

### 手机上打开（把链接发给她）

**本地文件发不过去。** 微信里发一个 `file:///C:/...` 的路径，她手机上打不开——
得先把这个页面托管到一个公网地址上，再把 `https://...` 的链接发给她。

这个页面是**单个自包含的 HTML**，没有任何构建步骤和外部依赖，所以任意静态托管都能直接用：
把 `preview` 这个文件夹整个传上去即可（`index.html` 就在根目录）。

常见的几个：

| 方式 | 说明 |
|------|------|
| Netlify Drop | 打开 `app.netlify.com/drop`，把 `preview` 文件夹拖进去，登录一次就有 `xxx.netlify.app` |
| Cloudflare Pages | 需要 Cloudflare 账号，产出 `xxx.pages.dev` |
| GitHub Pages | 用本仓库就行，但 Pages 只能选根目录或 `docs/`，得先把 `preview/index.html` 挪过去 |
| 微信云开发 · 静态网站托管 | 和本项目云函数同一个环境，域名在微信里最稳，但要先装开发者工具 |

> 注意：微信内置浏览器会拦截一部分域名，`netlify.app` / `pages.dev` 通常能开但不保证；
> 国内最稳的是云开发静态托管。

**还有个前提要说清楚**：这个网页是纯前端，没有后端。
她在她手机上点的单存在她手机浏览器里，**不会自动出现在你手机上**。
要做到「她点单、你手机能看到」，必须有后端——要么用云开发（本项目 `cloudfunctions/kitchen` 已经写好了），
要么给这个网页配一个在线存储。

## 开启双人同步（云开发）

> 云开发要在小程序自己的 AppID 下开通，游客模式不行。

1. **确认 AppID**：`project.config.json` 里的 `appid` 得是这个小程序自己的 AppID。
2. **开通云开发**：开发者工具顶部点「云开发」→ 开通 → 新建环境，复制**环境 ID**。
3. **填环境 ID**：打开 `config/cloud.js`，把环境 ID 填进 `ENV`。
4. **部署云函数**：在左侧文件树右键 `cloudfunctions/kitchen` → 
   **「上传并部署：云端安装依赖」**（必须选带「云端安装依赖」的那一项）。
5. **编译运行**：进入「我的 → 我们的小家」→ 点「创建我们的小家」，会拿到一个 6 位邀请码。
6. **让她加入**：她在自己的微信里打开这个小程序 →「我的 → 我们的小家」→ 输入邀请码。

### 她怎么打开这个小程序

开发阶段，只有**开发者和体验成员**能打开未发布的小程序：
微信公众平台 → 管理 → 成员管理 → 体验成员，把她的微信号加进去；
然后点开发者工具的「上传」，在公众平台把该版本设为**体验版**，把体验版二维码发给她。
（「预览」二维码只对开发者自己有效，发给她是打不开的。）

### 数据库权限（建议加固）

云函数以管理端身份访问数据库，客户端**完全不直连数据库**，所有读写都经过云函数校验成员身份。
所以功能上任何权限设置都能跑；但为了安全，建议在云开发控制台把第一次运行后自动创建的
4 个集合（`kitchens`、`orders`、`kitchen_menus`、`kitchen_profiles`）的权限都改成
**「所有用户不可读写」**，避免别人绕过云函数直接读写你的数据。

## 同步范围

| 数据 | 是否同步 | 说明 |
| --- | --- | --- |
| 菜单（新增 / 修改 / 售罄 / 删除） | 是 | 改完立刻推送，失败会打脏标记，下次进页面自动补推 |
| 订单 | 是 | 下单、接单、完成、取消、催单都以服务端为准 |
| 口味偏好（辣度 / 忌口） | 是 | 大厨那边能看到她不吃什么 |
| 购物车 | 否 | 各自手机各自的购物车 |
| 收藏、头像昵称、大厨身份 | 否 | 属于个人设置，不跨设备 |

**冲突策略**：菜单是「整份覆盖、后写生效」，你和她同时改菜单时，后改的会盖掉先改的
（菜单改动很少，实际几乎碰不上）。订单是「服务端为准」，每次进页面会拉最新状态。

**离线**：没配置环境、没配对、或网络不通时，小程序自动退回单机模式，功能照常用，
只是数据不会跨设备。

## 说明

- 数据以本机 `Storage` 为准，云端只是同步的另一份。所以**即使断网也不会白屏**，
  没配对时就是一台普通的单机点菜小程序。
- 本地存储的容量上限是 10MB / 单个 key 1MB。菜品做法是纯文本，正常用不会碰到上限；
  真到极限时 `dc_orders` 只保留最近 100 单，购物车和收藏会自动清理失效条目。
- 所有交互反馈（震动、Toast、Modal）都做了失败兜底，开发者工具里不会因为权限报错中断。
- 代码遵循小程序的保守语法：不使用可选链 `?.` 与空值合并 `??`，避免基础库版本差异导致的编译失败。
