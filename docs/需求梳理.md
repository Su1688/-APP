# 需求梳理 · 今天想吃什么

> 本文是早期过程稿，结论已全部并入正式版 `docs/需求文档.md`。

> 状态：需求确认中，尚未改动任何代码
> 更新：2026-09-16

## 1. 一句话

一个只服务一个人的点菜小程序：她在手机上点，你在手机上接单，中间夹着只有你们俩懂的彩蛋和情话。

## 2. 角色与场景

| 角色 | 在哪用 | 真正关心的事 |
| --- | --- | --- |
| 她（点菜的人） | 自己的手机 · 微信小程序 | 今天吃什么、点了你有没有看到、有没有惊喜 |
| 你（大厨） | 你的手机 · 同一个小程序切「大厨模式」 | 她点了什么、几点想吃、能不能回她一句 |

**场景 A｜日常（占 90%）**

她在公司或家里犯选择困难 → 打开小程序 → 点两三个菜、写个备注 → 下单 → 你手机看到 → 接单开做 → 做完点「做好啦」→ 她那边状态变成已完成。

**场景 B｜特殊日子（礼物向）**

纪念日 / 生日当天打开，首页自动切换成「专属菜单」：只放你们俩有故事的菜，配一段只有你们懂的话。平时藏起来，当天才出现。

## 3. 一条硬结论：必须有后端

「她在我手机上点单，我也能看到」= 跨设备同步，纯前端做不到。所以走：**小程序 + 微信云开发**。
本项目 `cloudfunctions/kitchen` 里的配对、菜单、订单、偏好同步逻辑已经写好。

前置条件只有两个：**一个 AppID**、**开通云开发环境并部署云函数**。

载体建议：**微信小程序为主**。理由：她微信里就有入口、不用记网址；订阅消息推送是现成的（她下单你手机响）；云开发与小程序同一套账号体系。
仓库里的 `preview/index.html` 网页版继续留着当演示页和截图素材，不占小程序包体积。

## 4. 功能清单

### P0 · 没有就不好用（现有代码基本已具备）

- 点菜：分类、搜索、菜品详情（食材 + 做法步骤）
- 购物车：加减份数、写备注、选「什么时候想吃」
- 下单 → 订单「待接单 / 制作中 / 已完成」三态流转 + 进度时间轴
- 云同步：她下单你能看到；你接单、做好她能看到
- 菜单管理：加菜、改菜、售罄、下架
- 口味偏好：辣度、忌口，同步给大厨
- 她怎么进来：把你加成体验成员、发体验版二维码

### P1 · 礼物向（重点做）

**自己做的菜拍照片**：加菜 / 改菜时直接拍照或从相册选，换掉 emoji；她点单时看到的是你真正做出来的那盘菜。

**纪念日菜单**：配置「日期 + 标题 + 菜 + 一段话」，当天首页自动出现入口，过了当天自动收起。

**彩蛋**（藏起来的小机关，不解释，等她自己发现）：

- 连点菜品图标 N 次 → 掉落爱心 / 花瓣
- 点「催单」时随机回一句撒娇话
- 搜索特定关键词（比如「想你」）出现一道隐藏菜
- 长按首页标题 → 出现一张你们的合照或一段话

**情话 / 小纸条**：订单流转时带动作文案（接单 →「马上做给你吃」，做好 →「快回来吃」），文案从本地池随机取，池子你自己可以加。

**大厨回话**：你接单时可以选一句回给她 —— 双向才好玩，单向那叫群发祝福。

**「今天吃什么」决定器**：她犯选择困难时转一下，随机帮她定一道。

### P2 · 锦上添花

- 吃完打分 → 慢慢筛出「她真正爱吃的」，影响首页招牌
- 订阅消息推送（她下单你响 / 你做好她响）
- 一起吃过的统计：多少顿、最常点的菜、第一次点的菜

## 5. 数据模型（新增部分）

- `dish` 加字段：`image`（自己拍的照片，可为空）、`secret`（是否彩蛋菜）、`unlockKey`（触发关键词）
- 新增 `moments`：纪念日 —— `{ date, title, dishIds, message, repeatYearly }`
- 新增 `loveNotes`：情话池 —— `{ scene: accept | cook | done | urge, text }`
- 新增 `easterEggs`：彩蛋配置 —— `{ type, target, threshold, payload }`
- `order` 加字段：`reply`（大厨回话）

> 礼物向的内容**大多是静态的**，直接内置在 `data/` 里即可，不必进云；只有订单和大厨回话需要同步。

### 5.1 菜品照片怎么落地

**字段**：菜品加 `image`，同时保留 `emoji` 当兜底 —— 没传照片的菜还是显示 emoji，不会出现空图。

**选图**：用 `wx.chooseMedia`（相册 + 拍照），传之前用 `wx.compressImage` 压到 800px 左右。原图动辄好几 MB，不压缩上传慢、云存储流量也吃不消。

**存哪儿**（这一点直接决定她能不能看到）：

| 场景 | 存法 | 结果 |
| --- | --- | --- |
| 只有你自己手机上看 | 本地文件系统 `saveFile` 到 `wxfile://usr/` | 免费、离线可用，但她那台手机看不到 |
| 要她也看得到 | 传云存储 `wx.cloud.uploadFile`，拿 `cloud://` 的 fileID | 跟着菜单同步走，她那边直接能显示 |

两个必须注意的点：

1. `wx.chooseMedia` 给的是**临时路径**（`wxfile://tmp_*`），重启小程序就失效，**不能直接存进菜品数据里** —— 单机模式必须 `saveFile`（或 `copyFile`）落地，联网模式必须上传云存储。
2. 本地的 `wxfile://usr/` 路径同步到她手机上**是打不开的**。所以「你拍的照片她也能看到」这个效果，绕不开云环境。

**一个容易漏的坑**：`utils/menu.js` 里的 `EDITABLE_FIELDS` 是保存白名单，新增 `image` 字段必须同步加进这个数组，否则保存时会被静默丢掉，现象是「选了照片，保存完就没了」。

**清理**：删菜或换图时要顺手删掉云存储里的旧文件，否则孤儿图片会一直堆积。

## 7. 需要你提供的内容（我编不出来的部分）

1. **她最爱吃 / 你最会做的 10~15 道菜**（决定菜单有没有灵魂）
2. **纪念日**：哪一天、什么名头、那天想显示的一句话
3. **你们之间的梗**：昵称、口头禅、只有你们懂的话
4. **情话风格**：土味 / 文艺 / 日常碎碎念（我按这个调子写池子）
5. **你有没有 AppID**：有就直接上云；没有我给你注册步骤（个人主体免费，约 1~2 天）
6. 有没有想放的**合照**（长按彩蛋用）

## 8. 里程碑

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| M1 | 她真的能用 | 换 AppID、开云环境、部署云函数、她进体验版、下单你能看到 |
| M2 | 礼物向内容 | 纪念日菜单 + 情话 + 彩蛋 + 决定器 |

## 9. 明确不做

- 多用户 / 开放注册（就你们俩）
- 支付、骑手、评价体系
- 后台管理系统（菜单管理在小程序里就够了）
- 商家端 / 多人厨房
