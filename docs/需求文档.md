## 1. 目标

一个只服务一个人的点菜小程序：她在手机上点，你在手机上接单，中间夹着只有你们俩懂的彩蛋和情话。

**怎么算做成了**

1. 她能自己打开并完成一次点单，全程不需要你教。
2. 她下单后，你的手机上能看到这条订单。
3. 你能在 1 分钟内加一道新菜、配一张自己拍的照片、删掉一道不做的菜。
4. 至少有一个彩蛋，是她自己发现后主动来跟你说的。

## 2. 角色

| 角色 | 谁 | 权限 |
| --- | --- | --- |
| 她（点菜的人） | 女朋友 | 点菜、下单、看订单、收藏、改口味偏好 |
| 你（大厨） | 你 | 上面全部，外加菜单管理、接单、做完了、回她一句话 |

> 同一个小程序，靠「我的 → 我来当大厨」开关分角色。**她的开关要保持关闭。**

## 3. 使用场景

**场景 A · 日常点菜（占 90%）**
她在微信里打开小程序 → 挑菜、加购物车 → 写备注、选时间 → 下单 → 你手机看到 → 接单开做 → 做完点「做好啦」→ 她那边变已完成。

**场景 B · 纪念日**
纪念日 / 生日当天打开，首页顶部换成「专属菜单」入口，只放你们俩有故事的菜，配一段话；第二天自动收起。

**场景 C · 选择困难**
首页一个按钮：「今天吃什么」随机帮她定一道，不满意可以再转一次。

**场景 D · 你上新菜**
我的 → 菜单管理 → 加新菜 → 拍照 → 填名字 / 分类 / 食材 / 步骤 → 保存 → 自动同步到她手机。

## 4. 形态与技术约束

- **载体**：微信小程序。她微信里就有入口、不用记网址，订阅消息推送也是现成的。
- **后端**：微信云开发，已开通并部署云函数 `kitchen`。
- **单机降级**：云不可用时自动退回本地存储，功能照常，只是数据不跨设备。
- **硬约束**：任何「她能看到 / 你能看到」的数据都必须走云端，纯前端做不到。

## 5. 功能需求与进度

### ✅ FR-1 浏览与点菜 [P0]
分类切换、按菜名 / 描述 / 标签搜索；卡片显示照片或 emoji、名字、介绍、标签、耗时、辣度；详情页有食材和做法步骤。

### ✅ FR-2 购物车与下单 [P0]
加减份数、写备注、选「什么时候想吃」；售罄的菜置灰且加不进购物车；提交后清空购物车。

### ✅ FR-3 订单流转 [P0]
状态：待接单 → 制作中 → 已完成；带进度时间轴、催单、取消、「照这个再来一单」。

### ✅ FR-4 配对与同步 [P0]
6 位邀请码配成「我们的小家」。同步菜单、订单、口味偏好；不同步购物车、收藏、头像昵称、身份开关。

### ✅ FR-5 菜单管理 [P0]
加菜、改菜、删除、标记「今日售罄」、一键恢复默认菜单。删掉的默认菜只是在本地藏起来，不破坏源码。

### ✅ FR-6 菜品照片 [P1]
- **范围**：一道菜一张封面图，不做多图、不做每步做法图。
- 加菜 / 改菜时可拍照或从相册选，能预览、换图、删图；上传前压缩到 900px 左右。
- 云可用时传云存储拿 `cloud://` fileID，她那台手机直接能看到；云不可用时存本机，编辑页会提示「她那台看不到」。
- 没传照片的菜回落显示 emoji，不出现空图。
- 删菜或换图时顺手删掉旧图（打包进包里的默认图不动）。

**已落地**：`utils/image.js`、编辑页拍照 UI、卡片与详情页渲染、云函数字段白名单。首页「蒜苗炒肉」已用真实照片验证通过。

### ✅ FR-7 口味偏好 [P0]
辣度、忌口，同步给大厨。

### ✅ FR-8 收藏 [P0]
详情页点爱心收藏，收藏页可一键加进购物车。

### 🚧 FR-9 纪念日菜单 [P1]
配置：日期、标题、菜品列表、一段话、是否每年重复。当天首页出现专属入口，过期自动收起。

### 🚧 FR-10 情话 / 小纸条 [P1]
场景：接单时 / 制作中 / 已完成 / 催单回复。文案从本地池随机取，可在「情话管理」里自己增删。

### 🚧 FR-11 大厨回话 [P1]
你接单时可以从预设里选一句回给她，显示在她的订单详情里。

### 🚧 FR-12 彩蛋 [P1]
连点菜品图标 N 次掉爱心 / 花瓣；点「催单」随机撒娇回复；搜索特定关键词出现隐藏菜；长按首页标题出现合照。
**约束**：不解释、不引导、不弹「你发现了彩蛋」这类提示，触发完能自然回到正常流程。

### 🚧 FR-13 「今天吃什么」决定器 [P1]
随机推荐一道在售的菜（排除售罄），带一点动画。

### 🚧 FR-14 消息推送 [P2]
订阅消息：她下单你收到 / 你做好她收到。需要她在小程序里授权一次。

### 🚧 FR-15 打分与统计 [P2]
「我的」页已有统计（点过的单 / 吃掉的份数 / 尝过的菜 / 最常点的是谁）。还差吃完打分，以及用打分影响首页「本店招牌」。

### 6.1 菜品照片怎么存

| 菜品来源 | `image` 存什么 | 她看得到吗 |
| --- | --- | --- |
| 打包进包的默认菜 | `/assets/dishes/xxx.jpg` | 看得到，图跟着小程序包走 |
| 你自己加的菜（已配云开发） | 云存储的 `cloud://` fileID | 看得到，跟着菜单同步过去 |
| 你自己加的菜（没配云开发） | 本机用户目录 `wxfile://usr/` | 看不到 |

`wx.chooseMedia` 返回的是**临时路径**，重启小程序就失效，不能直接存进菜品数据 —— 落地统一在 `utils/image.js` 处理。

> **容易漏的坑**：`utils/menu.js` 的 `EDITABLE_FIELDS` 和云函数 `sanitizeDish` 都是字段白名单，新增字段要两处都加，否则会被静默丢掉。

## 8. 非功能需求

- **性能**：首页首屏 1.5 秒内出内容；图片一律压缩后上传。
- **离线**：断网 / 未配对时自动降级为单机，不白屏、不报错。
- **容量**：小程序主包上限 2MB，目前约 267KB，余量充足；本地 storage 上限 10MB，订单只保留最近 100 单。
- **兼容**：不使用可选链 `?.` 与空值合并 `??`，避免基础库版本差异导致编译失败。
- **隐私**：数据库设为「所有用户不可读写」，客户端不直连数据库，读写全走云函数并校验成员身份。

## 10. 上线流程：她怎么才能用上

1. 云开发控制台 → 数据库 → 把 `kitchens`、`orders`、`kitchen_menus`、`kitchen_profiles` 的权限都改成「所有用户不可读写」。
2. 后台 mp.weixin.qq.com → 管理 → 成员管理 → 体验成员 → 添加她的微信号。
3. 开发者工具右上角「上传」→ 后台 → 版本管理 → 把该版本设为「体验版」→ 把体验版二维码发给她。
4. 她扫码打开 → 我的 → 我们的小家 → 输入你的 6 位邀请码。
5. 建议她点右上角「···」→「添加到我的小程序」，以后从微信首页下拉就能进。

> **注意**：开发者工具里的「预览」二维码只有你自己能扫，发给她打不开。
> 微信搜索搜不到未发布的小程序，这是正常的；要能被搜到得走「提交审核 → 发布」，而且审核要选对服务类目（**别选餐饮 / 食品类，个人主体没资质**）。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 她不用 | 全白做 | 先把 M1 走通，确认她愿意用，再做 M2 礼物向内容 |
| 云开发配额 / 流量超支 | 图片加载失败甚至产生费用 | 上传前强制压缩，单张控制在 300KB 以内 |
| 提交审核被拒 | 无法发布 | 服务类目选「工具 / 生活服务」，不碰餐饮食品类 |
| 彩蛋做得太刻意 | 尴尬，反而减分 | 不提示、不弹窗、藏进正常交互里 |
| 换了手机或清了数据 | 本地数据丢失 | 菜单、订单、偏好都在云端有备份，重新输邀请码即可 |
