# 第一部分 · 已定但还没做（FR-9 ~ FR-15）

## FR-9 纪念日菜单

**目的**：让某几个日子跟平时不一样。

**数据**（内置在 `data/moments.js`）

```js
{
  id: "day-100",
  date: "12-24",                          // MM-DD 每年重复，或 YYYY-MM-DD 只出现一次
  repeatYearly: true,
  title: "我们在一起的第 100 天",
  message: "今天想吃什么都行，我全做。",
  dishIds: ["suanmiao-chaorou"],          // 留空数组 = 直接用全部菜单
  cover: "/assets/moments/day100.jpg"     // 可选
}
```

**交互**

1. 打开首页 → 判断今天有没有命中某个 moment。
2. 命中 → 首页顶部出现一张**卡片**（不是弹窗，不打断她），上面是标题和那句话，右下角「看看今天的菜单」。
3. 点进去是 `pages/moment`：顶部是标题和那段话，下面是那天的菜（只显示 dishIds 里的，或全部）。
4. 从专属菜单里照样能加购物车、下单，走的是完全一样的流程。
5. 没命中 → 首页跟平时一模一样，不多任何东西。

**边界**

- 同一天命中多条（生日撞上纪念日）→ 只显示 `date` 最精确的那一条，避免堆叠。
- 日期按**本机本地时间**判断，不用 UTC，避免半夜跨天出错。
- `data/moments.js` 为空 → 完全不出现入口，也不报错。

**验收**：把系统日期改到纪念日 → 首页出现卡片、点进去只有指定的菜；改成第二天 → 卡片消失，首页恢复原样。

**需要你给**：哪一天、什么名头、那天想让她看到的那句话、想放哪几道菜。

## FR-10 情话 / 小纸条

**目的**：状态变化要说人话，不要冷冰冰的「订单已更新」。

**四个场景**

| scene | 什么时候出现 | 我觉得合适的调子 |
| --- | --- | --- |
| `accept` | 你点「接单开做」之后，她的订单详情 | 收到，这就去给你做 |
| `cook` | 制作中，她翻看订单时 | 锅里已经在咕嘟了 |
| `done` | 你点「做好啦」之后 | 快回来吃，凉了就不好吃了 |
| `urge` | 她点「催单」之后 | 马上马上，再等我 5 分钟 |

**交互**

- 状态一变，订单详情页顶部多一条**手写感的小纸条**（浅底色、圆角、稍微歪一点点）。
- 每次从对应场景的池子里随机取一条，同一单内不重复。
- 「我的 → 情话管理」可以自己增删改，改动存在本机（不跨设备）。

**边界**

- 池子为空 → 不显示纸条，不报错。
- 反复触发同一场景（她连点催单）→ 每次换一条，取完一轮后重新开始。

**验收**：连续下三单，每次你接单后她看到的文案不完全相同。

## FR-11 大厨回话

**目的**：让「接单」像一次对话，而不是一次点击。

**交互**

1. 你在订单上点「接单开做」→ 弹出半屏面板，列 5~8 句预设话。
2. 选一句 → 订单变成制作中，那句话出现在**她的订单详情**里。
3. 也可以点「不说了」直接跳过，不影响接单。
4. 她能看到，但不能回复 —— 保持单向，别让它变成聊天工具，微信已经够用了。

**验收**：她在自己手机上看到你选的那句话。

---

## FR-12 彩蛋

四条，全部藏起来、不解释、不写进任何给她看的说明。

| 编号 | 触发 | 表现 |
| --- | --- | --- |
| E1 | 首页快速连点某道菜的图片 5 次 | 屏幕上方掉落爱心 / 花瓣，2 秒后消失，不影响任何操作 |
| E2 | 她点「催单」 | 除了正常催单，订单上多一句随机撒娇（复用 FR-10 的 `urge` 池） |
| E3 | 搜索框输入特定关键词（比如「想你」「抱抱」） | 菜单里多出一道平时不显示的菜 |
| E4 | 长按首页标题 1.5 秒 | 浮现一张合照或一段话，松手消失 |

**统一约束**

- 不弹「你发现了彩蛋」这类提示。
- 触发后不改变任何数据，纯粹好玩。
- 她自己摸索出来的才算彩蛋，你告诉她的不算。

**验收**：你自己每个都能触发；她不看代码不会提前知道。

## FR-13 「今天吃什么」决定器

**交互**：首页搜索框旁边一个骰子按钮 → 点一下，菜名快速滚动 1 秒 → 停在一道上 → 显示「就它了」，旁边一个「加进购物车」。

**边界**：排除售罄的菜；菜单为空时按钮不出现；允许重复抽到同一道（真随机比假随机自然）。

**验收**：连点三次，结果大概率不同。

---

## FR-14 消息推送 [P2]

她下单后你手机收到提醒 / 你做好后她收到提醒。用的是微信订阅消息，需要她授权一次。
细节等到要做的时候再定 —— 因为它涉及订阅消息模板申请，可能要等审核。

## FR-15 吃完打分 [P2]

「我的」页已经有统计了（点过的单 / 吃掉的份数 / 尝过的菜 / 最常点的是谁）。还差：

- 订单完成后，她可以给这顿饭打 1~5 星 + 一句短评。
- 打分结果影响首页「本店招牌」：分高的排前面，不用再靠点单次数。

# 第二部分 · 建议新增（你还没提，我觉得该有）

> 这部分是提议，不是已定。你觉得不合适直接划掉，我们不做。

## FR-16 许愿菜 [建议 P1]

**为什么**：现在她只能在你给的菜单里点。可她偶尔会馋一样菜单上没有的东西 —— 这时候她只能退出小程序来跟你说，那个体验就断了。

**怎么做**：购物车底部或者首页一个「想吃点别的」→ 她打一道菜名 + 一句想说的话 → 提交。
这条**不进购物车、不算订单**，单独进你的「愿望」列表。你可以「安排上」（自动加进菜单）或「改天吧」（回复她一句）。

**为什么我觉得它比彩蛋重要**：这是全app里唯一一个**她主动发起**的功能。彩蛋是你逗她，许愿是她跟你说想吃。

## FR-17 买菜清单 [建议 P1]

**为什么**：你在厨房真正需要的是「今天要买什么」，不是「她点了什么」。现在你得自己一道道菜去翻食材。

**怎么做**：订单页或大厨首页一个「汇总食材」→ 把当天所有订单的 `ingredients` 去重合并 → 生成一份能打勾的清单。

**一个限制**：食材现在是自由文本（「五花肉 500g」），只能按行去重，**没法自动合并数量**（两份菜都要五花肉，会显示两行 500g）。要精确合并，得把食材改成结构化数据，那是另一件事了。

## FR-18 「大厨今天休息」 [建议 P2]

你在「我的」页开一个开关，打开后她那边的下单按钮变灰，显示「大厨今天休息」。

**为什么**：她点了你却不做，比不点更伤。提前关掉，比事后解释轻松。

## FR-19 纪念日倒计时 [建议 P2，谨慎]

首页角落显示「距离 XX 还有 N 天」。

**为什么我标了谨慎**：纪念日提醒是双刃剑。你自己记得的话它多余；你自己忘了的话，它每天在她眼前倒计时，等于给你上刑。**建议先不做**，等 FR-9 用一段时间再说。

# 第三部分 · 开发顺序建议

| 顺序 | 做什么 | 为什么排这个位置 |
| --- | --- | --- |
| 1 | FR-10 情话 + FR-11 大厨回话 | 不依赖任何新数据，改动最小，但每天点单都能感受到 |
| 2 | FR-13 决定器 + FR-12 彩蛋 | 也是纯前端，做完就有「这个小程序有点东西」的感觉 |
| 3 | FR-9 纪念日菜单 | 要你给日期，做完一次性生效 |
| 4 | FR-16 许愿菜 + FR-17 买菜清单 | 需要动云函数和数据结构，但实用度最高 |
| 5 | FR-18 休息开关 | 很小，顺手 |
| 6 | FR-14 推送 + FR-15 打分 | 都要审核或改数据结构，放最后 |

**一句话建议**：先让我把 1、2 做完（不需要你提供任何东西，也不用动数据库），你和她先用起来。用着用着你就知道该先做哪个了 —— 现在拍板顺序，不如让她点两单之后再定。
