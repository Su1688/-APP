# 开工前的准备工作

> 你只需要做下面这些，代码是我的活。按顺序做，前两步做完就可以先告诉我结果。

## 第 1 步 · 装工具并导入项目（约 10 分钟）

1. 下载安装「微信开发者工具」稳定版：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
2. 打开后**用你自己的微信扫码登录**（必须是这个小程序的注册微信，不要选「游客模式」）。
3. 选「导入项目」，目录填：

   `C:\Users\Administrator\Documents\ChatGPT\做菜小程序开发`

4. AppID 填：`wx609b29f982871158`
5. 导入后点一下「编译」。能看到点菜页面，就说明环境没问题了。

## 第 2 步 · 开通云开发，拿环境 ID —— 已完成

环境名称 `cloud1`，环境 ID `cloud1-d3g2jgvk22b11d8ad`，已填入 `config/cloud.js`。

1. 开发者工具顶部点「云开发」→ 开通。
2. 首次开通会让你确认套餐，按最低档来（新用户通常有免费额度，具体金额以控制台为准）。
3. 新建一个环境，名字随意（比如 `diancai`、`home` 都行，它只是个称呼，跟代码没有任何关系）。
4. 建好后进「设置」，复制**环境 ID**（形如 `cloud1-xxxxxxxx`）。
5. 把这串 ID 发我，我填进 `config/cloud.js`。

**为什么必须现在做**：照片要同步给她、订单要同步给你，全靠这个环境。没有它，你拍的照片只能存在你自己手机上，她看不到。

## 第 3 步 · 部署云函数（约 2 分钟）

> 先分清三个名字，很容易混：
> `cloud1` 是**环境名称**，只是个称呼，随便叫；
> `cloud1-d3g2jgvk22b11d8ad` 是**环境 ID**，填进 `config/cloud.js` 的就是它；
> `kitchen` 是**云函数的名字**，来自项目里的 `cloudfunctions/kitchen` 目录。
> 一个环境里可以放多个云函数，`kitchen` 只是其中一个。

1. 开发者工具左上角确认 AppID 是 `wx609b29f982871158`；顶部「云开发」里确认环境是 `cloud1-d3g2jgvk22b11d8ad`。
2. 左侧文件树展开 `cloudfunctions`，找到 `kitchen` 目录。
3. **右键 `kitchen` 文件夹** → 选「**上传并部署：云端安装依赖**」。
   - 别选「所有文件」：会把本地依赖一起传上去，慢而且容易出错。
   - 别选「仅上传」：不装依赖，云函数一调用就报错。
4. 右下角提示「上传成功」后，打开云开发控制台 → 云函数，能看到 `kitchen` 就成了。
5. 第一次调用会自动建 4 个集合：`kitchens`、`orders`、`kitchen_menus`、`kitchen_profiles`。
6. 建好后去云开发控制台 → 数据库，把这 4 个集合的权限都改成「**所有用户不可读写**」——
   客户端不直连数据库，读写全走云函数，这样别人就不能绕过校验直接读你们的数据。

**为什么必须选「云端安装依赖」**：`kitchen` 依赖 `wx-server-sdk`，本地没有 `node_modules`，要让云端装。

> **以后每次我动了 `cloudfunctions/kitchen`，你都要把第 3 条重做一遍**（右键 `kitchen` →「上传并部署：云端安装依赖」）。
> 最近一次动了云函数是为了加 `imageUrls`（图片链接签发），**需要重新部署一次**。
> 只改了页面的话不用部署，点一下「编译」就行 —— 判断方法：我在改动记录里写了「必须重新部署」的要部署，没写的不用。

**怎么算成功**：小程序里「我的 → 我们的小家 → 创建我们的小家」，能拿到 6 位邀请码，就说明云函数通了。

**卡住了看这里**

| 现象 | 原因 |
| --- | --- |
| 右键菜单里没有「上传并部署」 | `project.config.json` 的 `cloudfunctionRoot` 不对（本项目已配好，是 `cloudfunctions/`） |
| 报「没有权限」 | 开发者工具登录的微信号不是这个小程序的管理员 |
| 部署成功但「创建小家」失败 | 云开发控制台 → 云函数 → `kitchen` → 日志，看具体报错 |

## 第 4 步 · 把要用的人加成体验成员（约 2 分钟，每人一次）

1. 打开 mp.weixin.qq.com 登录小程序后台。
2. 管理 → 成员管理 → 体验成员 → 添加。
3. 填她的微信号。

> 小家默认能装 **4 个人**。每个人都要在这里加一次，少一个都打不开体验版；
> 「我的 → 我们的小家」里那个 `x/4 人已连接` 就是当前进来的人数。
> 体验成员有数量上限（一般 15 个），够用。

**不做这步，她扫二维码也打不开你的小程序。**

## 第 5 步 · 设置小程序名称和头像（可选）

后台 → 设置 → 基本设置。她会在微信里看到这个名字，值得花五分钟想一下。
名称需要审核，1~2 天，但不影响开发。

## 第 6 步 · 只有你能给的内容（随时给我）

1. **10~15 道菜**：菜名 + 做法（有细节就一起给，没有我按常规写法补）。
2. **纪念日**：日期、什么名头、那天想显示的一句话。
3. **你们之间的梗**：昵称、口头禅、只有你们懂的话。
4. **情话风格**：土味 / 文艺 / 日常碎碎念。
5. **合照**：想放进长按彩蛋的话，给我一张。

## 菜品照片怎么给我（重要）

云开发免费环境的云存储权限锁死在「仅创建者可读写」，控制台点「权限」想改会弹「当前套餐处于免费期，无法执行此操作，请升级至付费版使用」。
也就是说：照片存到云存储后，**只有你自己能读**，她那台只会显示一块灰底。

已经解决：云函数里加了一个 `imageUrls`，用管理员身份把 fileID 换成带签名的 https 链接，谁都能看。
小程序端渲染图片前会先走它（结果缓存 25 分钟左右），**不需要你改云存储权限，也不用升级付费版**。

**所以加图有两种方式，按需选：**

| 方式 | 怎么做 | 要不要改代码 | 她什么时候看到 |
| --- | --- | --- | --- |
| 自己加（推荐日常用） | 菜单管理 → 加菜 / 改菜 → 拍照或选图 → 保存 | 不用 | 自动同步，秒级 |
| 发我进代码包 | 原图发我 → 我压到 900px 存进 `assets/dishes/` | 要改一次 + 你重新上传体验版 | 她更新体验版之后 |

什么时候用代码包：招牌菜、包内默认菜（比如「蒜苗炒肉」「红烧寸排」），好处是随包下发、离线也在、不依赖云开发。

> ⚠️ 小程序**主包上限 2MB**，现在整个包才 0.39MB。菜图都塞进包里，大约 15 张就会顶到上限，
> 所以日常加菜走「自己加」，代码包只留给几道招牌菜。

> 部署提醒：这次动了云函数（新增 `imageUrls`），记得右键 `cloudfunctions/kitchen` →
> 「上传并部署：云端安装依赖」，否则她看到的老版本云函数不认这个操作，图片会退回灰底。

## 你不用管的

- 改 `project.config.json` 里的 AppID
- 写云函数、填环境配置、部署（部署那一下可能要你在工具里点一次「上传并部署：云端安装依赖」，到时我给你一步步的说明）
- 数据库权限加固（第一次跑通后，把自动创建的 4 个集合改成「所有用户不可读写」）
- 所有代码

## 提前知道一件事：她怎么才能用上

开发者工具里的「预览」二维码**只有你自己能扫**，发给她是打不开的。正确流程是：

1. 我改完代码
2. 你在工具里点「上传」
3. 后台把这个版本设为「体验版」
4. 你把体验版二维码发给她

所以每次有更新都要走一遍这四步。M1 做完我们会完整走一次，走通了她就能天天用了。
